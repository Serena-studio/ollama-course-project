# 进出口代理单证一致性智能体系统 · 技术方案

> 文档编号：AGENT-DOCS-001 · 合成演练项目 · 本方案所有业务事实均标注来源编号（f00–f54），模拟数据均已声明。
> 声明：合成演练 · 不代表真实授权、业务执行或客户验收。

## 1. 项目概述

### 1.1 项目背景
客户为上海外综服国际贸易有限公司（合成演练场景），进出口代理单证业务链路五段：**客户提供 → 单证检查 → 人工确认 → 委托作业 → 归档**（f01）。现场痛点：
- 发票、装箱单与订单的商品名称和单位不一致（f10）；
- 客户更新装箱数量但商业发票版本未同步导致返工（f11，模拟异常）；
- 现场习惯先群消息解决再补填表格，回填时间不能当作发生时间（f13）；
- 代理单证包无统一关联编号（f30）。

演练基线"每月 220 票、每票核对 42 分钟"为虚构样本（f12），不作为设计依据或收益测算。

### 1.2 系统定位
本系统是"**定位与提示**"工具，不是审批或放行系统。核心交付物：**一页缺项清单 + 对应来源位置（定位到原单据字段）**，供人工确认使用（f15/f42）。智能体只承担：字段一致性比对、版本双条件判定、差异来源定位、人工队列分派提醒；不承担：审批、放行、覆盖原值、对外结论、自动申报归类或监管判断（f14/f22）。

### 1.3 验收口径
- 50 票样本预设差异全部定位到原单据字段（f02）；
- 每条结果关联来源与人工复核记录（f42）；
- 质量三条：异常可拦截、结论可追溯到授权人、越权访问为零（f41/f44）。

## 2. 需求要点与数据红线

P0 需求三条：
1. **缺项清单+来源定位**替代泛化摘要（f15/f42）；
2. **版本有效期 + 确认状态双条件**判定最新版本，作废保留原因，不靠文件名猜版本（f24）；
3. **异常存疑一律进人工队列**，不默认通过（f44）。

七条数据红线（硬约束，全部落到代码）：

| # | 红线 | 事实来源 | 落地方式 |
|---|------|----------|----------|
| 1 | 只读边界：只对接脱敏只读导出，无写回/执行接口 | f32 | 系统仅提供 POST /api/import 单向导入自有库；无任何回写源系统的接口 |
| 2 | 人工队列：存疑一律入队并暂停，禁默认通过/自动重试/编造状态 | f44/f35 | manual_queue 表 + redlines.manual_queue_on_doubt 配置开关（阶段3 实现流转） |
| 3 | 双时间戳：业务发生时间 ≠ 系统接收时间；过期来源不覆盖已确认新版本 | f34/f13 | versions 表 business_time 与 system_time 双列，导入时分离写入 |
| 4 | 字段口径：白名单六项；缺失与未确认严格区分 | f31 | config.field_whitelist + missing_marker/unconfirmed_marker 双标记 |
| 5 | 版本判定：有效期+确认状态双条件，禁按文件名猜 | f24 | versions 表 is_effective + confirm_state 双列，唯一约束防重 |
| 6 | 审计留痕：谁查过/哪个版本/什么建议/谁确认，不留摘要 | f45/f43 | audit_logs 表全量 detail JSON；查询即留痕 |
| 7 | 数据性质：输出固定携带"合成演练"声明；未定口径前无物理删除 | 简报/f43 | 所有响应 data.disclaimer；系统无 DELETE 接口 |

## 3. 总体架构

### 3.1 技术栈（锁定，不许替换）
- **Python 3.11+**（当前开发环境 3.13）
- Web 框架：FastAPI（接口统一前缀 `/api`）
- 存储：SQLite 单文件（sqlite3 标准库，不用 ORM）
- 配置：PyYAML，全部集中于 `config.yaml`（模型地址、密钥占位符、白名单、链路节点）
- LLM：仅经 OpenAI 兼容接口调用，模型名与地址从 config.yaml 读取（演练模型 deepseek-flash，可配置替换）
- 页面：FastAPI + Jinja2（阶段4 缺项清单页），不做独立前端
- 测试：pytest + httpx
- 明确不引入：Docker、Celery、MongoDB、Redis、消息队列、云服务 SDK

### 3.2 模块结构
```
agent-system/
├── config.yaml              # 全局唯一配置（红线开关/角色权限/白名单/链路）
├── requirements.txt         # 依赖锁定
├── app/
│   ├── main.py              # FastAPI 入口（lifespan 建表）+ 接口
│   ├── config.py            # 配置加载（环境变量覆盖机制）
│   ├── db.py                # 连接管理 + 五类表建表（幂等）
│   ├── response.py          # 统一响应结构唯一构造入口
│   ├── importer.py          # 只读导入器（幂等、整包事务、审计留痕）
│   ├── checker.py           # （阶段2）白名单校验/双条件判定/缺项清单
│   └── samples/             # 合成样本 JSON
├── tests/
│   └── test_stage1.py       # 阶段1 验证 Harness（6 用例）
└── scripts/
    └── run_harness.py       # 一键跑批入口
```

### 3.3 数据流
```
合成样本 JSON（只读导出）
        │  POST /api/import（幂等，整包事务）
        ▼
SQLite 五类表 ──► /api/packs/{id} 只读查询（先验权限 f41，查询即审计 f45）
        │
        ▼ （阶段2）
checker 比对引擎 ──► 缺项清单 + 来源定位（f15/f42）
        │
        ▼ （阶段3）
存疑项 ──► manual_queue 人工队列 ──► 业务负责人确认（f22，模型无审批权）
        │
        ▼ （阶段4）
审计报告 + 50 票验收脚本 + Jinja2 清单页面
```

## 4. 数据模型（五类表）

| 表 | 关键字段 | 对应红线 |
|----|----------|----------|
| `documents` 单证表 | pack_id, doc_type, doc_no, payload(JSON 原行), source_file | f33 保留原行 / f42 关联来源 |
| `versions` 版本表 | doc_id, version_no, is_effective, confirm_state, void_reason, valid_until, business_time, system_time | f24 双条件 / f34 双时间戳 / f43 保留原因 |
| `handovers` 交接表 | pack_id, node(五段), from_role, to_role, version_no, open_items, deadline | f20/f23 交接四要素 |
| `audit_logs` 审计表 | actor, role_key, action, pack_id, doc_id, version_no, detail(JSON 全量) | f45 不留摘要 |
| `manual_queue` 人工队列 | pack_id, doc_id, reason, status(open/confirmed/paused), resolved_by | f44 不默认通过 |

样本数据内置两颗"异常种子"用于阶段2 比对验证：P2026-002 装箱单 v2 有效但未确认（f11 版本未同步模拟异常）；P2026-003 装箱单单位"打"与发票/订单"件"不一致（f10 字段不一致）。

### 4.1 缺项清单输出结构（阶段2 交付物格式定义）

缺项清单是本系统对外的**核心交付物**（f15/f42），一页、可逐行核对，字段固定如下——阶段2 的比对引擎必须严格按此结构输出，不允许增删字段：

| 字段 | 含义 | 约束来源 |
|------|------|----------|
| `pack_id` / `doc_no` | 单证包、单据号 | 关联 documents 原行（f33） |
| `field` | 命中的字段名 | 仅限六项白名单（f31） |
| `status` | `missing` / `unconfirmed` / `mismatch` | 缺失与未确认必须分列（f31） |
| `values` | 各单据该字段的值 + 来源文件名 | 必须定位到原单据字段（f15） |
| `source_ref` | 文件 + 页/行 + 版本号 | 可回溯（f42） |
| `suggested_action` | 补件 / 请业务负责人确认 | 只提示，不决定（f14/f22） |
| `human_confirm` | 确认人 + 确认时间 | 空即未确认，**禁止预填**（f41） |

硬约束：清单中**不允许出现"通过/驳回/放行"类结论字段**。放行不是本系统职权（f22），清单只负责让人更快地做判断。

## 5. 接口设计

统一响应结构：`{"ok": bool, "data": ..., "error": {"code": str, "msg": str}}`

### 5.1 统一错误码

| code | 触发条件 | 状态 |
|------|----------|------|
| `SAMPLE_INVALID` | 样本文件缺失、JSON 非法、交接节点不在五段链路内 | ✅ 阶段1 已实现 |
| `FORBIDDEN` | 角色未登记，或无该单证包查询权限（未知角色按最小权限拒绝） | ✅ 阶段1 已实现 |
| `NOT_FOUND` | `pack_id` 不存在 | ✅ 阶段1 已实现 |
| `QUEUE_CONFLICT` | 同一存疑项重复入队 | 阶段3 计划 |
| `CONFIRM_DENIED` | 非唯一确认人尝试确认放行 | 阶段3 计划 |

说明：当前未预期异常由框架默认 500 返回，阶段2 补全局异常处理器，统一转成 `INTERNAL_ERROR`，且**错误详情不回传前端**（避免泄露表结构）。

| 接口 | 方法 | 状态 | 说明 |
|------|------|------|------|
| `/api/health` | GET | ✅ 阶段1 | 健康检查，携带演练声明 |
| `/api/import` | POST | ✅ 阶段1 | 只读导入合成样本（幂等，审计留痕） |
| `/api/packs/{pack_id}` | GET | ✅ 阶段1 | 单证包只读查询（先验权限 f41，查询即审计） |
| `/api/packs/{id}/checklist` | GET | 阶段2 | 缺项清单+来源定位（f15/f42） |
| `/api/packs/{id}/versions/judge` | GET | 阶段2 | 版本双条件判定结果（f24） |
| `/api/queue` / `/api/queue/{id}/confirm` | GET/POST | 阶段3 | 人工队列流转与确认（f44/f22） |
| `/api/audit` | GET | 阶段4 | 审计检索（仅 auditor 角色，f45） |
| `/api/acceptance` | POST | 阶段4 | 50 票验收脚本执行（f02） |

权限矩阵（config.yaml `roles`，代码强制）：一线专员可查可提变更**不可确认**；业务负责人为唯一 `can_confirm=true`；模型角色 `can_confirm` 硬编码 false **不允许配置覆盖**（f22）；未知角色按最小权限全 False 处理（f41 越权为零）。

## 6. 关键设计决策

1. **查询即审计**：成功查询必须先写 audit_logs 再返回（f45）——审计写失败则中断响应，不允许"查了但没记"。
2. **导入幂等 + 整包事务**：以单证表存在性判断跳过；任一交接节点不在五段链路内整包回滚——宁拒不脏（f01 口径一致性）。
3. **双时间戳分离写入**：business_time 来自样本（业务发生时间），system_time 由库默认值生成——从表结构上杜绝"回填时间当发生时间"（f13）。
4. **配置即红线**：redlines 段全部默认安全值，代码启动即加载校验，配置坏了拒绝启动——红线优先于可用性。
5. **最小权限默认**：未知角色返回全 False 权限集，而不是报错放行（f41）。

## 8. 测试 Harness

一键跑批：`python scripts/run_harness.py`，内部依次执行：
1. 环境自检（Python ≥3.11、依赖可导入）；
2. `pytest tests/ -v` 全量用例；
3. 输出汇总（通过数/失败数/耗时），非零退出码表示不合格。

当前用例清单（阶段1，6 个）：健康检查统一结构、导入幂等、查询结构（双时间戳/来源标注）、未知角色 FORBIDDEN、NOT_FOUND 业务错误、审计留痕落库。阶段2 起每阶段追加用例，Harness 持续累积。

## 9. 运行与部署

- 环境要求：Python 3.11+（开发验证于 3.13）
- 安装：`python -m pip install -r requirements.txt -i https://pypi.org/simple/`
- 自测：`python -m pytest tests/test_stage1.py -v`
- 启动：`python -m uvicorn app.main:app --reload --port 8000`（接口文档 `/docs`）
- 密钥：通过环境变量 `AGENT_LLM_KEY` 注入，禁止写入任何文件

## 10. 风险与待确认项

- SQLite 多进程并发写会 `database is locked`（演示单写者可接受，阶段3 引入写接口时需评估）；
- 样本文件必须 UTF-8 编码，GBK 编码将被导入器拒绝（刻意设计）；
- 待业务口径确认后再实现：保留期限与删除审批（f43）、过期阈值、快照保留时长与中断分级（f35）——未确认前一律不写入规则；
- 50 票样本抽取人与预设差异清单维护人未定（阶段4 前需确认）。
